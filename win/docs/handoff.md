# 윈도우 쪽에서 이어받을 때

[← 윈도우판 README](../README.md) · 작업 규칙은 [`../CLAUDE.md`](../CLAUDE.md)

윈도우판은 처음에 **맥에서, 화면을 한 번도 보지 못한 채로** 만들어졌다. WPF 가 맥에서
컴파일되지 않았기 때문이다. **2.0.0 에서 윈도우로 개발을 옮기며 그 벽이 걷혔다** —
띄워 보고 눌러 가며 고쳤고, 무엇이 확인됐는지는 [`../CLAUDE.md`](../CLAUDE.md) 에 있다.

아래 글을 그대로 윈도우의 Claude Code 에 붙여 넣으면 된다.

---

```
이 저장소(dong-csu)의 윈도우판 개발을 이어받아 줘.

먼저 이 세 문서를 읽어:
  win/CLAUDE.md   윈도우 전용 작업 규칙 — 프로젝트 구성, 진단 통로, 배포, 그릴 때 걸리는 것
  CLAUDE.md       공통 규칙 — 버전 자리, 변경 내역 문구, 커밋 규칙
  win/README.md   사용자에게 보이는 설명

지금 상태:
- 최신 릴리스는 win-v2.4.0. 안 나간 변경이 쌓여 있다(변경 내역 맨 위, 날짜 없는 항목)
- 개발은 테스트판으로 한다: ./build.ps1 -Test -Run
  설정·기록·자동 시작이 정식판과 갈려 있어 둘을 같이 띄워 비교할 수 있다
- 기능은 맥에서 먼저 만들어 윈도우로 옮긴다. 맥 버전은 저장소 태그를 봐라
- 펫 모드까지 옮겨 왔다. 움직임 규칙은 DongCSU.Core 의 PetMotion 에 있고
  가짜 시계·가짜 화면으로 테스트된다 — 앱을 안 띄우고 확인할 수 있다

지켜야 할 것:
- 부엉이 그림을 여기서 고치지 마라. 원본은 맥 소스이고 shared/owl.json 으로 넘어온다.
  레이어 겹치기(OwlComposer)와 **자세를 만드는 규칙**(걷기·매달림)만 옮겨 적혀 있고,
  테스트가 그 결과를 맥이 뽑아 둔 프레임과 글자 단위로 대조한다
- 화면이 아닌 것은 DongCSU.Core 에 둬라. 거기 있어야 어디서나 테스트된다.
  움직임·측정·서식처럼 시계나 화면 크기가 필요한 것은 주입받아서 테스트가 시계 없이 돌게 해라
- 윈도우는 버전 네 번째 자리를 못 쓴다(설치본이 SemVer2 세 자리만 받는다).
  긴급 수정도 세 번째 자리로 올린다
- **버전 자리를 정하거나 태그를 붙이기 전에 반드시 나에게 물어봐라**
- 커밋은 제목 한 줄만. `[Win] 🐛 한국어 한 줄` 처럼 어느 판인지 앞에 붙인다
  (맥은 `[Mac]`, 양쪽에 걸리거나 어느 쪽도 아니면 안 붙인다)

화면을 고쳤으면 실제로 띄워서 눌러 보고, 무엇이 되고 무엇이 안 되는지 알려 줘.
```

### 5시간 한도가 없는 계정 (Ultra)

**인증이 끝난 Ultra 계정은 사용량 API 가 `"five_hour": null` 을 준다.** 키를 빼는 게
아니라 `null` 이고, `limits` 배열에도 `session` 이 없다. 인증 전에는 임시 5시간 한도가
걸려 있어서 **요금제 이름으로 가르면 안 된다** — 조회할 때마다 응답을 본다.

맥과 같은 셋을 옮겼다.

| | 맥 | 윈도우 |
| --- | --- | --- |
| 판정 | `UsageAPI.isExplicitlyAbsent` | `UsageApi.IsExplicitlyAbsent` → `UsageSnapshot.HasSessionLimit`. 키가 없으면 모름(있다고 본다) |
| 화면 | 세션 줄·링을 빼고 안쪽 링을 바깥으로 당긴다 (`Card.hasThirdRing`) | `HudView.RingEntries` 한 곳이 몇 겹인지 정하고, 그리기·가운데 그림 자리·카드 크기가 다 그걸 본다 |
| 기분 | `OwlMood.resolve` 가 주간으로 | `UsageStore.TiringUtilization` 이 고른다 — `OwlMoodResolver` 는 계정 모양을 모른다 |

`--probe-hud` 가 **5시간 한도 유무까지 96가지**를 돈다. 링 둘이 큰 카드 안에서 헐렁해지는
것은 창 안이라 안 잘려서 눈으로는 못 잡는다.

### 계정 고르기 (맥 2.7.0) — 아직 안 옮겼다

**걸리는 것은 `claude auth login` 하나다.** 맥은 계정마다 설정 폴더를 하나 만들어
`CLAUDE_CONFIG_DIR` 로 그 폴더에 로그인시키고, 로그인을 **터미널 없이** 띄운다(표준 입력이
비어도 브라우저를 열고 로컬 콜백을 기다리는 것을 확인했다). 윈도우에서는 둘 다 아직 확인하지
못했다.

**CLI 는 데스크톱 앱 안에 있다.** 따로 안 깔았어도 Claude 데스크톱 앱이
`%LOCALAPPDATA%\Claude-Data\claude_<프로필>\claude-code\<버전>\<해시>\claude.exe` 에
깔아 둔다(`ClaudeCli.DesktopRoot`). 거기에 `auth login` 이 있다. **다만 데스크톱 앱 자신은
로그인을 앱 안에 들고 Claude Code 에 넘겨줘서 `~/.claude/.credentials.json` 의 Claude
로그인을 새로 고치지 않는다** — 그 파일을 MCP 칸 때문에 다시 쓰면서도 Claude 로그인은 두 달
전 것 그대로 두는 것을 봤다. 데스크톱 앱으로만 쓰는 사람에게 재로그인이 꼭 필요한 이유다.

옮기기 전에 먼저 재 볼 것:

- `CLAUDE_CONFIG_DIR=<폴더>` 로 로그인하면 자격 증명이 **`<폴더>\.credentials.json`** 에
  생기는지 (맥은 키체인 자리 이름에 경로 해시를 붙인다 — 윈도우는 파일이라 다를 것이다)
- 콘솔 없이(`CreateNoWindow` · 표준 입력 리디렉트) 띄워도 브라우저가 열리고 콜백을
  받아 끝나는지. Ink 가 raw mode 를 못 잡아 바로 죽을 수도 있다
- 기본 로그인(`~/.claude`)이 그대로인지 — 맥은 전후를 찍어 확인했다

나머지(프로필 조회 `/api/oauth/profile`, 계정마다 `token-<id>.json`, 계정마다 조회 상태,
측정은 재기 시작한 계정 것만)는 맥 [`ClaudeAccounts.swift`](../../mac/Sources/DongCSU/ClaudeAccounts.swift)
· `UsageStore.AccountState` 를 그대로 따르면 된다. 걸리는 것은 [`mac/CLAUDE.md`](../../mac/CLAUDE.md)
의 "여러 계정" 절에 있다.

**옮길 때도 화면 없는 부분을 먼저 `Core` 에 넣고 테스트로 굳혀라.** 맥 쪽 구현은
`mac/Sources/DongCSU/` 에 있고, 규칙과 이유는 [`mac/CLAUDE.md`](../../mac/CLAUDE.md) 에 있다.

## 윈도우가 맥과 일부러 다르게 한 것

옮기다 보면 "왜 다르지" 싶은 자리들이다. 되돌리기 전에 이유를 보라.

| | 맥 | 윈도우 | 왜 |
| --- | --- | --- | --- |
| CPU 표시 | 코어 하나 기준(한 코어를 다 쓰면 100%) | **전체 코어 기준** | 견줄 상대가 작업 관리자다. 8코어에서 800%가 뜨면 버그 신고가 된다 |
| 메모리 기준 | `phys_footprint` | 작업 집합 | 위와 같은 이유 |
| 갱신한 토큰 | keychain 에 **되돌려 쓴다** | `%APPDATA%\DongCSU\token.json` 에만 둔다 | 아래를 보라 |
| 펫 복귀 지점 | 저장 안 함 | **저장함** | 파일 설정에서는 공짜다. 펫으로 껐다 켜도 원래 보기로 돌아온다 |
| 펫 링 지름 | 123 (선을 지름 안에 넣음) | **123** | 2.5.0 에서 124 → 123 으로 맞췄다. 안 잘리는 것은 우리도 같지만 **두 판의 링 크기가 1pt 달랐다** |
| 넘어갈 때 설 수 있는 자리 | 어느 한 화면에 **온전히** 들어가야 한다 | **부풀린 창의 네 귀퉁이**가 저마다 어느 화면 안이면 된다 | 맥 방식이면 화면 사이에 창 폭+16 의 죽은 띠가 생겨 한 걸음(2.6)으로 못 건넌다 |
| 계정 탭 초 갱신 | 탭을 통째로 다시 그린다 | **만료 글자 하나만 갈아 끼운다** | 그리는 김에 자격 증명 파일을 훑어서, 매초 그리면 WSL 을 1초마다 깨운다 |
| 창 목록 | `CGWindowListCopyWindowInfo` | `EnumWindows` + **`DWMWA_EXTENDED_FRAME_BOUNDS`** | `GetWindowRect` 는 보이지 않는 잡는 테두리(좌·우·아래 7~8px)까지 세서, 그대로 붙이면 옆·아래에서만 펫이 뜬다 |
| 안 붙었을 때 기록 | 테스트판만, **따로 된 파일**(`dong-csu-test-perch.log`)에 창 목록째 | 같은 `log.txt` 에. **정식판은 한 줄만**(그림 자리 · 아이콘), 창 목록은 테스트판만 | 윈도우 기록은 원래 한 파일이고 512KB 에서 갈아엎는다. 정식판에서 빠진 것은 남의 **앱 이름·창 자리**뿐이라 "안 붙었다" 자체는 남는다 |
| 두 번 띄우기 | LaunchServices 가 알아서 하나만 둔다 | `SingleInstance` — 판마다 이름 붙은 뮤텍스. 두 번째 것은 먼저 뜬 쪽을 불러내고 물러난다 | 윈도우에는 그런 것이 없다. 트레이에만 떠서 켜진 줄 모르고 또 띄우는 일이 잦았다 |

## 리프레시 토큰은 회전하고, 쓴 것은 즉시 죽는다 — 둘 다 확인했다

맥에서 `--probe-refresh` 로 실제로 재 봤다. 서버는 갱신할 때마다 **새 리프레시 토큰을
주고**, 한 번 쓴 토큰으로 다시 갱신하면 **곧바로 실패한다.** 여태 "회전하는 경우가
많다"는 짐작으로 두었던 자리인데, 이제 사실이다.

그래서 **갱신하는 쪽이 이긴다.** 우리가 갱신하면 Claude Code 가 들고 있던 값은 그
순간 죽고, 그쪽은 다음에 갱신하려다 로그인이 풀린다. 윈도우에서 아직 안 터진 건
거기서 Claude Code CLI 를 안 쓰기 때문이지 안전해서가 아니다.

**윈도우가 되돌려 쓰지 않는 이유는 허락 창 때문이 아니다.** 맥은 키체인이라 쓸 때
사용자에게 한 번 묻지만, 윈도우의 `.credentials.json` 은 그냥 파일이라 아무것도 묻지
않는다. 그쪽 걸림돌은 **동시에 쓰면 섞인다**는 것뿐이다. 비용만 놓고 보면 윈도우가
오히려 싸다.

맥은 **회전했을 때만** 새 값을 원래 자리(키체인)에 되돌려 써서 두 쪽을 맞춰 둔다.

**윈도우도 같은 문제를 안고 있지만 같은 방법을 쓸 수 없다.**

| | 맥 | 윈도우 |
| --- | --- | --- |
| 저장 자리 | 키체인 | `.credentials.json` **파일** |
| 되돌려 쓰기 | `SecItemUpdate` — 원자적이고 순서가 보장된다 | 둘이 동시에 쓰면 **파일이 섞여 로그인이 통째로 날아간다** |

임시 파일에 쓰고 바꿔치기하면 찢어지는 건 막지만, **우리가 읽은 뒤 Claude Code 가
먼저 갱신해 버린 경우**는 못 막는다. 옮겨 올 때 그 부분을 어떻게 할지부터 정해야 한다.

맥 쪽 구현은 `mac/Sources/DongCSU/TokenRefresh.swift` 와 `UsageAPI.swift` 의
`CredentialStore` 에 있고, 되돌려 쓸 때 **읽어 둔 원문에 얹어서 통째로 다시 쓴다** —
`mcpOAuth` 처럼 우리가 모르는 항목을 지우지 않으려는 것이다. 윈도우도 같아야 한다.
