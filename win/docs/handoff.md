# 윈도우 쪽에서 이어받을 때

[← 윈도우판 README](../README.md) · 작업 규칙은 [`../CLAUDE.md`](../CLAUDE.md)

윈도우판은 처음에 **맥에서, 화면을 한 번도 보지 못한 채로** 만들어졌다. WPF 가 맥에서
컴파일되지 않았기 때문이다. **2.0.0 에서 윈도우로 개발을 옮기며 그 벽이 걷혔다** —
띄워 보고 눌러 가며 고쳤고, 무엇이 확인됐는지는 [`../CLAUDE.md`](../CLAUDE.md) 에 있다.

아래 글을 그대로 윈도우의 Claude Code 에 붙여 넣으면 된다.

---

```
이 저장소(dong-csu)의 윈도우판 개발을 이어받아 줘.

먼저 이 세 문서를 읽어:
  win/CLAUDE.md   윈도우 전용 작업 규칙 — 프로젝트 구성, 진단 통로, 배포, 그릴 때 걸리는 것
  CLAUDE.md       공통 규칙 — 버전 자리, 변경 내역 문구, 커밋 규칙
  win/README.md   사용자에게 보이는 설명

지금 상태:
- 최신 릴리스는 win-v2.0.1. 안 나간 변경이 쌓여 있다(변경 내역 맨 위, 날짜 없는 항목)
- 개발은 테스트판으로 한다: ./build.ps1 -Test -Run
  설정·기록·자동 시작이 정식판과 갈려 있어 둘을 같이 띄워 비교할 수 있다
- 기능은 맥에서 먼저 만들어 윈도우로 옮긴다. 맥 버전은 저장소 태그를 봐라
- 펫 모드까지 옮겨 왔다. 움직임 규칙은 DongCSU.Core 의 PetMotion 에 있고
  가짜 시계·가짜 화면으로 테스트된다 — 앱을 안 띄우고 확인할 수 있다

지켜야 할 것:
- 부엉이 그림을 여기서 고치지 마라. 원본은 맥 소스이고 shared/owl.json 으로 넘어온다.
  레이어 겹치기(OwlComposer)와 **자세를 만드는 규칙**(걷기·매달림)만 옮겨 적혀 있고,
  테스트가 그 결과를 맥이 뽑아 둔 프레임과 글자 단위로 대조한다
- 화면이 아닌 것은 DongCSU.Core 에 둬라. 거기 있어야 어디서나 테스트된다.
  움직임·측정·서식처럼 시계나 화면 크기가 필요한 것은 주입받아서 테스트가 시계 없이 돌게 해라
- 윈도우는 버전 네 번째 자리를 못 쓴다(설치본이 SemVer2 세 자리만 받는다).
  긴급 수정도 세 번째 자리로 올린다
- **버전 자리를 정하거나 태그를 붙이기 전에 반드시 나에게 물어봐라**
- 커밋은 제목 한 줄만. `[Win] 🐛 한국어 한 줄` 처럼 어느 판인지 앞에 붙인다
  (맥은 `[Mac]`, 양쪽에 걸리거나 어느 쪽도 아니면 안 붙인다)

화면을 고쳤으면 실제로 띄워서 눌러 보고, 무엇이 되고 무엇이 안 되는지 알려 줘.
```

| 맥에 있는 것 | 윈도우 |
| --- | --- |
| 펫 모드 (혼자 돌아다니기 · 커서 피하기) | 2.1.0 에서 옮김 |
| 마스코트 애니메이션 끄기 | 2.0.0 에서 옮김 |
| 모든 설정 초기화 · 위치 초기화 | 2.0.0 에서 옮김 |
| 아이콘 고르기 (Clawd · Claude 아이콘 · 버스트 마크) | 2.0.0 에서 옮김 |
| HUD 크기 4단계 · 배경 불투명도 | 2.0.0 에서 옮김 |
| 접기/펼치기 애니메이션 (0.22초) | 2.1.0 에서 옮김 — **펫 전환만 일부러 곧바로** 바꾼다 |
| 재로그인을 앱에서 바로 실행 | 없음 — 계정 탭이 안내만 한다 |

**옮길 때도 화면 없는 부분을 먼저 `Core` 에 넣고 테스트로 굳혀라.** 맥 쪽 구현은
`mac/Sources/DongCSU/` 에 있고, 규칙과 이유는 [`mac/CLAUDE.md`](../../mac/CLAUDE.md) 에 있다.

## 윈도우가 맥과 일부러 다르게 한 것

옮기다 보면 "왜 다르지" 싶은 자리들이다. 되돌리기 전에 이유를 보라.

| | 맥 | 윈도우 | 왜 |
| --- | --- | --- | --- |
| CPU 표시 | 코어 하나 기준(한 코어를 다 쓰면 100%) | **전체 코어 기준** | 견줄 상대가 작업 관리자다. 8코어에서 800%가 뜨면 버그 신고가 된다 |
| 메모리 기준 | `phys_footprint` | 작업 집합 | 위와 같은 이유 |
| 갱신한 토큰 | keychain 에 **되돌려 쓴다** | `%APPDATA%\DongCSU\token.json` 에만 둔다 | 아래를 보라 |
| 펫 복귀 지점 | 저장 안 함 | **저장함** | 파일 설정에서는 공짜다. 펫으로 껐다 켜도 원래 보기로 돌아온다 |

## 리프레시 토큰은 회전한다 — 확인했다

맥에서 `--probe-refresh` 로 실제로 재 봤다. **서버는 갱신할 때마다 새 리프레시 토큰을
준다.** 여태 "회전하는 경우가 많다"는 짐작으로 두었던 자리인데, 이제 사실이다.

그래서 **갱신하는 쪽이 이긴다.** 우리가 갱신하면 Claude Code 가 들고 있던 값은 그
순간 죽고, 그쪽은 다음에 갱신하려다 로그인이 풀린다. 윈도우에서 아직 안 터진 건
거기서 Claude Code CLI 를 안 쓰기 때문이지 안전해서가 아니다.

맥은 **회전했을 때만** 새 값을 원래 자리(키체인)에 되돌려 써서 두 쪽을 맞춰 둔다.

**윈도우도 같은 문제를 안고 있지만 같은 방법을 쓸 수 없다.**

| | 맥 | 윈도우 |
| --- | --- | --- |
| 저장 자리 | 키체인 | `.credentials.json` **파일** |
| 되돌려 쓰기 | `SecItemUpdate` — 원자적이고 순서가 보장된다 | 둘이 동시에 쓰면 **파일이 섞여 로그인이 통째로 날아간다** |

임시 파일에 쓰고 바꿔치기하면 찢어지는 건 막지만, **우리가 읽은 뒤 Claude Code 가
먼저 갱신해 버린 경우**는 못 막는다. 옮겨 올 때 그 부분을 어떻게 할지부터 정해야 한다.

맥 쪽 구현은 `mac/Sources/DongCSU/TokenRefresh.swift` 와 `UsageAPI.swift` 의
`CredentialStore` 에 있고, 되돌려 쓸 때 **읽어 둔 원문에 얹어서 통째로 다시 쓴다** —
`mcpOAuth` 처럼 우리가 모르는 항목을 지우지 않으려는 것이다. 윈도우도 같아야 한다.
