# macOS 판 작업 규칙

공통 규칙(버전 자릿수·변경 내역 문구·캐릭터·커밋)은 [`../CLAUDE.md`](../CLAUDE.md)에 있다.
여기에는 **맥에서만 걸리는 것**을 쓴다.

**모든 명령은 `mac/` 안에서 돌린다.** 아래 경로는 전부 `mac/` 기준이다.

## 버전

```bash
./release.sh 1.0.0.1
```

버전은 `Resources/Info.plist`와 `Sources/DongCSU/main.swift` 두 곳에 있고
release.sh가 양쪽을 함께 올린 뒤 어긋나지 않았는지 확인한다.
태그는 `mac-` 을 붙인다 — 윈도우와 번호를 따로 세기 때문이다.

## 변경 내역

[`Sources/DongCSU/Changelog.swift`](Sources/DongCSU/Changelog.swift) 맨 위 항목에 한 줄
추가하고, 앱이 원격에서 받아보는 JSON을 다시 뽑는다.

```bash
source ./lib.sh && dump_changelog
```

**반드시 이 함수를 쓴다** — 직접 `--dump-changelog`를 부르면 빌드를 건너뛰어
옛 바이너리가 방금 추가한 항목을 빠뜨린 채 뽑는다.

**같은 것이 두 곳에 나간다.** `mac/docs/changelog.json`이 진짜고, 저장소 뿌리의
`docs/changelog.json`은 **이미 나간 2.0.0 이하가 아직 그 주소를 보고 있어서** 남겨 둔
사본이다. 함수가 둘 다 쓰고 CI가 둘 다 검사한다. 다들 2.1.0을 넘기면 뿌리 쪽은 지운다.

## 빌드

검증은 **test 변형으로만** 한다.

```bash
VARIANT=test ./build.sh     # DongCSU-Test.app
```

`./build.sh`(정식 번들)는 배포할 때 release.sh가 알아서 부른다. 개발 중에 직접 만들면
사용자가 brew로 설치해 쓰는 배포본이 바뀐 것처럼 보여서 혼란스럽다. 실수로 만들었으면
`build/DongCSU.app`을 지운다.

**빌드했다고 화면에 반영되지 않는다.** 이미 떠 있는 앱은 옛 바이너리 그대로다.
`dev.sh`(fswatch)가 돌고 있지 않다면 직접 다시 띄운다.

```bash
pkill -f DongCSU-Test; open build/DongCSU-Test.app
```

## 눈으로 확인하기

앱을 띄우지 않고도 대부분을 PNG로 뽑아 볼 수 있다. 화면에 영향을 주는 변경은
이걸로 먼저 확인한다.

```bash
dong-csu --render out.png 34 61 owl ok large      # HUD (사용률·아이콘·상태·배율)
dong-csu --render-settings out.png changelog      # 설정 창의 특정 탭
dong-csu --probe-layout                           # 설정 창이 탭마다 얼마나 길어지는지
dong-csu --render-menubar out.png 16              # 메뉴바 아이콘
dong-csu --render-icon out.png 1024               # 앱 아이콘
dong-csu --render-owl out.png 96                  # 부엉이 애니메이션 전 프레임 (기분 + 걷기·달리기)
dong-csu --render-owl-gif ../docs/characters/owl  # 하나마다 움직이는 GIF (문서용)
dong-csu --dump-owl ../shared/owl.json            # 윈도우판과 나눠 쓸 부엉이 데이터
dong-csu --dump-sprites <디렉터리> [sheet]        # 부엉이를 그림 마스코트 형식으로 (예시·검증용)
dong-csu --fit-sheet <시트.png> [나올.json]       # 그린 시트에서 칸 좌표 뽑기
dong-csu --probe-perch [selftest]                 # 창에 붙는 계산 · 붙여 둔 것이 버티는지
dong-csu --probe-login [on|off]                   # 로그인 항목 등록 상태 확인·변경
dong-csu --probe-tokens 30                        # 최근 30분 동안 Claude Code가 쓴 토큰
dong-csu --probe-meter [selftest|scan]            # 측정 기록 확인
dong-csu --probe-refresh [write|sync]             # 토큰 갱신 · 회전 여부 확인
```

## 토큰 갱신

**앱이 스스로 갱신한다.** 만료된 토큰을 만나면 키체인의 리프레시 토큰으로 새로 받는다.

한동안은 갱신을 Claude Code에게 맡겼다. 리프레시 토큰이 회전하면 우리가 먼저 써버린
값이 무효가 되어 Claude Code 로그인이 풀리기 때문이었다. **그 전제가 틀렸다** —
Claude Code를 데스크톱 앱으로만 쓰면 키체인 토큰을 갱신해 줄 사람이 아무도 없다.
`claude --version` 을 돌려 봐도 키체인은 그대로다. 그래서 다섯 시간마다 재로그인
안내만 뜨는 상태가 된다.

### 회전하고, 쓴 것은 즉시 죽는다 — 둘 다 확인했다

`--probe-refresh` 로 실제로 재 봤다. 서버는 **매번 새 리프레시 토큰을 주고**, 한 번 쓴
토큰으로 다시 갱신하면 **곧바로 실패한다.** 그래서 되돌려 쓰기는 취향이 아니라 필수다 —
안 쓰면 우리가 갱신하는 순간 Claude Code가 들고 있는 값이 죽는다.

| | 어디에 | 언제 |
| --- | --- | --- |
| 우리 사본 | `~/Library/Application Support/<번들 ID>/token.json` | **항상** |
| 되돌려 쓰기 | 키체인 (Claude Code와 공유) | **회전했을 때만** |

되돌려 쓰기도 **읽기와 같은 `/usr/bin/security`** 를 쓴다. 이유가 두 가지다.

**하나 — 허락 창이 버전마다 뜨지 않게.** 키체인 허락은 코드 서명 신원에 걸리는데 이 앱은
ad-hoc 서명이라 신원이 **바이너리 해시**다. 앱이 직접 `SecItemUpdate` 를 부르면 버전을
올릴 때마다 해시가 바뀌어 **사용자에게 다시 묻는다.** `security` 는 Apple이 서명해서 신원이
고정이고 읽기로 이미 허용돼 있어서 아무것도 묻지 않는다.

**둘 — 토큰이 프로세스 목록에 안 드러나게.** 명령을 인자가 아니라 **표준 입력**으로 준다
(`security -i`). 아래 두 길은 실제로 재 보고 버렸다.

| 시도 | 왜 버렸나 |
| --- | --- |
| `security ... -w "<값>"` | 토큰이 **argv 에 그대로** 실린다 |
| `-w` 만 주고 값을 표준 입력에 | **128바이트에서 잘린다.** 항목이 3KB를 넘어서 자격증명이 깨진다 |
| `SecItemUpdate` | 우리 신원이라 **버전마다 허락을 다시 묻는다** |

쓸 때는 읽어 둔 원문에 얹어서 통째로 다시 쓴다. `mcpOAuth` 처럼 우리가 모르는 항목이
같이 들어 있어서, 새로 만들면 그것들이 지워진다. **account 를 반드시 붙인다** — 서비스
이름만 주면 같은 이름을 쓰는 다른 항목까지 덮어쓴다.

되돌려 쓰기가 실패하면 `KeychainWriteBack` 이 한동안 다시 시도하지 않는다. 그동안 앱은
제 사본으로 계속 돌고, Claude Code 쪽 토큰만 낡은 채로 남는다.

`--probe-refresh sync` 로 우리 사본을 키체인에 손으로 맞춰 넣을 수 있다.

**인증서를 만들어 배포하는 길은 접었다.** 신원을 고정하려면 개인키를 CI에 둬야 하는데,
그 키가 새면 그걸 쥔 사람이 만든 앱을 macOS가 같은 앱으로 보고 **사용자가 허용해 둔
키체인 접근을 물려받는다.** 창 한 번 덜 뜨자고 질 위험이 아니다.

**윈도우는 아직 되돌려 쓰지 않는다.** 거기는 저장소가 파일이라 동시에 쓰면 섞일 수
있어서 방법이 달라야 한다. 자세한 건 [`win/docs/handoff.md`](../win/docs/handoff.md).

## 측정

시작~중지 사이에 얼마나 썼는지를 **두 가지로** 잰다. 재는 범위가 달라서 하나만으로는
답이 안 된다.

| | 잡는 범위 | 눈금 |
| --- | --- | --- |
| 한도 %p | 계정 전부 — Claude Code·클로드 앱·웹 | 1%p (서버가 정수로 준다) |
| 토큰 수 | **Claude Code만** | 토큰 단위 |

한도는 사용량 API에서 오고 어디서 쓰든 같은 창을 깎는다. 토큰은
`~/.claude/projects/**/*.jsonl` 을 읽는데, **클로드 앱·웹은 이 기계에 아무것도 남기지
않는다.** 두 값이 안 맞는 게 정상이고, 그 차이가 대략 앱에서 쓴 몫이다.

기록은 `~/Library/Application Support/<번들 ID>/meter.json` 에 있다. 설정이 아니라
데이터라서 UserDefaults에 넣지 않았고, "모든 설정 초기화"에 딸려 지워지지도 않는다.

**중지하면 그 측정이 목록에 남는다.** 다시 시작해도 목록은 안 지운다 — 지우면 다시
시작 한 번에 여태 쌓은 것이 통째로 날아간다. 화면은 위에 펼쳐 놓은 측정을 목록에서
빼서, 같은 것이 위아래로 두 번 보이지 않게 한다.

**HUD·펫의 측정 버튼은 화면을 열기만 한다.** 거기서 바로 재기 시작하면 손이 스칠
때마다 재던 것이 끊기고, 무엇이 시작됐는지도 화면에 안 보인다.

### 걸리는 것

- **리셋을 넘겨서도 쌓는다.** 5시간 창은 재는 도중에 반드시 새로 열리는데, 그냥 빼면
  그때 기록이 날아간다. `resets_at` 이 바뀌면 새 창에서 쓴 몫을 그대로 더한다.
  다만 **초 단위로 견주지 않는다** — 마이크로초 지터를 리셋으로 세면 표본마다
  소모량이 통째로 더해져 값이 터진다. `--probe-meter selftest` 가 이 계산을 검사한다
- **같은 응답이 두세 줄에 걸쳐 적힌다.** 값은 매번 같아서 `message.id` 로 처음 것만 센다.
  세지 않으면 두 배가 된다
- **세션을 이어가면 옛 응답이 새 파일로 통째로 복사된다.** 오프셋만으로는 이걸 못 거른다.
  복사본은 원래 시각을 달고 오므로 시작 시각으로 한 번 더 거른다
- **훑은 결과에는 어느 측정 것인지 표식을 달아 대조한다**(`SessionStamp`). 파일을 읽는
  동안 메인 액터가 풀려서, 그 틈에 다시 시작이나 계속을 누르면 옛 결과가 새 측정 위에
  떨어진다 — 옛 토큰이 더해지고 새로 잡은 오프셋이 옛 자리로 **되감긴다.** 한 번
  되감기면 그 뒤 모든 훑기가 같은 구간을 다시 읽어서 값이 계속 커진다.
  중지는 표식을 안 바꾸므로 마지막 훑기는 통과한다
- **일시정지에서 돌아올 때 기준을 새로 잡는다.** 오프셋을 지금 파일 끝으로 옮기고
  한도는 다음 표본을 더하지 않고 기준만 옮긴다(`needsRebaseline`). 안 그러면 세워 둔
  동안 쓴 것이 측정에 들어간다. 잰 시간에서도 멈춰 있던 만큼을 뺀다
- **조회를 조르지 않는다.** 시작·계속·중지는 곧바로 한 번 조회를 부탁하지만, 30초 안에
  또 부탁하지 않고 `force` 로도 쏘지 않는다. force 는 429 백오프를 무시해서 요청 제한을
  더 부른다 — 실제로 걸렸다

`--probe-login` 은 **번들 기준**이라 터미널에서 불러도 앱과 같은 것을 본다. 확인하고
나면 원래 상태로 되돌려 놓는다 — 안 그러면 테스트판이 로그인할 때마다 뜬다.

`--render-owl`은 `OwlAnimation.all`을 한 장에 늘어놓는다. 자세를 고칠 때 앱을 띄우고
몇 초씩 기다리지 말고 이걸로 본다. **걸음걸이는 기분이 아니라서 `OwlMood.allCases`에 없다**
— 보여줄 것을 더할 자리는 `OwlAnimation.all` 한 곳이다. 다만 **크기가 달라 보인다는 인상은 재지 말고
픽셀로 확인한다** — 주저앉은 자세는 다리가 몸에 가려져 실제로 한 칸 짧다.

**자세나 프레임 시간을 고쳤으면 `--render-owl-gif`를 다시 돌린다.** 캐릭터 문서의
GIF가 실제 애니메이션과 어긋나면 안 된다. GIF는 손으로 만들지 않는다.

## 그림 마스코트

사용자가 제 그림을 넣는 통로다. **부엉이를 대체하지 않는다** — 부엉이는 파츠를 겹쳐
그리는 쪽을 계속 쓰고, 이건 그 위에 얹힌 갈래다. 상태 판정은 `OwlAnimator.spriteState`
하나에서 나와서 두 갈래가 같은 판단을 한다.

`~/Library/Application Support/<번들 ID>/mascot/` 에 넣는다.

| | |
| --- | --- |
| `mascot.png` | 칸을 나눠 담은 한 장 (6×4). 없으면 낱장 `<상태>.png` 를 찾는다 |
| `mascot.json` | 칸마다 어느 자리를 읽을지. **없으면 균등 격자로 나눈다** |

### 크기를 못 박고 칸을 선으로 가른다

**규격은 `1543 x 1029` (또는 그 정수배).** 한 칸 256, 칸 사이와 바깥에 1px 선.
이 크기로 오면 좌표를 **우리가 이미 알고 있어서** 아무것도 찾아내지 않는다.

```
가로 = 6칸 x 256 + 7선 x 1 = 1543
세로 = 4칸 x 256 + 5선 x 1 = 1029
칸 (열 c, 행 r) = x: 1 + c*257, y: 1 + r*257, 256 x 256
```

**선은 어느 칸에도 안 들어간다.** 칸 자리를 선 굵기만큼 밀어 놨기 때문에, 그리는
사람이 선을 지우든 남기든 그림에는 영향이 없다. 칸 경계를 눈으로 보여주면서 그림은
안 더럽히는 유일한 방법이다.

```bash
dong-csu --dump-sprites out.png sheet rules empty   # 빈 틀 (그리는 사람에게 준다)
dong-csu --dump-sprites out.png sheet               # 부엉이 예시 (앱에 넣는 형식)
dong-csu --dump-sprites out.png sheet rules x2      # 규격의 2배로
```

읽는 순서는 **적어 둔 좌표 → 규격 좌표 → 균등 분할** 이다. 손으로 적은 `mascot.json`
이 가장 세다 — 규격에서 벗어난 그림을 구제하려고 적는 것이라 우리가 덮으면 뜻이 없다.
다만 **좌표가 그림 밖으로 하나라도 나가면 그 좌표표는 통째로 버린다.** 시트만 바꿔 놓고
옛 좌표를 남겨 두면 엉뚱한 조각이 들어가는데, 그림이 나오기는 해서 왜 이상한지 알 수 없다.

### 좌표를 찾아내는 건 구제용이다

```bash
dong-csu --fit-sheet mascot.png
```

**넣을 때 자동으로 부르지 않는다.** 한동안 그렇게 해 놨는데 거꾸로였다 — 찾아낸 좌표가
맞는지 우리가 알 수 없고, **반쯤 맞는 좌표는 균등 분할보다 나쁘다.** 균등 분할은 적어도
틀리는 방식이 예측 가능한데, 칸 크기가 제각각인 좌표는 여백 자르기가 통째로 꺼지고
상관없는 칸까지 몇 pt씩 어긋난다.

규격을 안 지킨 그림을 받았을 때 사람이 손으로 부르고, 찍힌 좌표를 **눈으로 보고** 적는다.

| 끝 | 언제 |
| --- | --- |
| `0` | 배치와 칸 수가 맞다 |
| `2` | 적기는 했는데 배치와 어긋난다. **눈으로 맞춰 봐야 한다** |
| `1` | 못 찾았다. **아무것도 안 적는다** |

**칸이 하나로 잡히면 실패로 친다.** 그림 전체가 한 칸이 됐다는 뜻이라, 그대로 적어 두면
앱이 시트를 통째로 `idle` 한 장으로 읽는다. 배경을 안 지운 그림(편집기의 체커무늬를
진짜 픽셀로 그린 것)이 정확히 이 꼴이고, 그때는 그렇다고 알려 준다.

### 칸마다 따로 가운데를 맞추지 않는다

여백을 걷어낼 때 **모든 칸을 감싸는 상자 하나**로 자른다. 칸마다 알맹이에 딱 맞춰
자르면, 걸을 때 몸이 좌우로 기우는 것(`OwlAnimator.gaitPose` 의 `lean`)처럼 **그림
안에 그려 넣은 움직임이 통째로 사라진다.** 같은 이유로 `--fit-sheet` 도 알맹이에 딱
맞는 상자가 아니라 칸을 뽑는다.

## 다른 앱 창 읽기

펫을 창 테두리에 붙이려고 **다른 앱 창이 화면 어디에 있는지** 읽는다.
[`WindowSurvey`](Sources/DongCSU/WindowSurvey.swift) 한 곳에서만 읽는다.

**권한이 하나도 안 든다.** `CGWindowListCopyWindowInfo` 는 손쉬운 사용도 화면 기록도
묻지 않고 `bounds`·`ownerPID`·`layer`·`alpha` 를 준다 — 창 46개로 직접 재 봤고 허락
창은 한 번도 안 떴다. 못 받는 것은 **창 제목(`kCGWindowName`) 하나뿐**인데 우리는
제목을 안 본다. 그래서 위 "서명" 절의 전제(권한을 안 써서 자체 서명 인증서가 아직
필요 없다)가 이 기능으로 깨지지 않는다.

> "제목만 권한이 걸린다"를 못 박은 **Apple 문서는 없다.** 헤더에도 문서에도 그런 말이
> 없어서 근거는 실측과 `sharingState` 상관뿐이다. 설계 근거로 쓰는 건 괜찮지만
> "Apple 이 그렇게 문서화했다"고 적지 마라.

**화면 기록 권한을 받는 길은 접었다.** 제목이 딸려 오지만 그 순간 `make-signing-cert.sh`
가 필수가 되고 Sequoia 이후의 주기적 재확인 창까지 온다. 창 하나 고르자고 치를 값이 아니다.

### 걸리는 것

- **`.optionAll` 을 쓰지 마라.** 53개가 385개가 되고 그중 대부분이 다른 스페이스에
  있거나 한 번도 안 뜬 유령 창인데, `kCGWindowIsOnscreen` 키가 아예 없어서 걸러낼
  수도 없다. **앞뒤 순서가 보장되는 것도 지금 스페이스만 나오는 것도
  `.optionOnScreenOnly` 일 때뿐이다** — 붙어 있던 창이 다른 스페이스로 넘어간 것을
  "목록에서 사라졌다"로 알아챈다
- **PID 필터가 진짜 방어선이다.** HUD 패널은 layer 3 이라 `layer == 0` 에 저절로
  걸리지만 **설정 창은 보통 창이라 layer 0 으로 뜬다.** 빼먹으면 설정 창을 여는 순간
  펫이 제 설정 창에 매달린다
- **`bounds` 는 픽셀이 아니라 포인트다.** 배율로 나누지 마라
- 좌표는 **세로만 주 화면 높이 하나로 뒤집으면** 모니터가 몇 대든 맞는다.
  `NSScreen.main` 을 쓰면 안 되는 이유는 `defaultOrigin()` 주석과 같다
- **창이 움직이는 것을 알림으로 받는 길이 없다.** AX 알림은 권한이 필요하고
  `NSWorkspace` 알림은 앱 단위라 창 이동과 무관하다. 폴링뿐인데 목록 한 번이
  0.3ms 도 안 걸려서 문제가 안 된다. 마우스로 끄는 중일 때만 촘촘히 보되
  **바닥 주기를 반드시 남긴다** — 단축키로 창을 옮기는 도구는 마우스 이벤트를 안 낸다

### 붙는 자리는 그림에서 잰다

매달린 칸은 손이 그림 상자 위쪽에, 앉은 칸은 발이 아래쪽에 그려져 있다. 상자를 그대로
테두리에 대면 자세마다 수십 pt 씩 떠서 **매달린 것이 아니라 공중에 뜬 것으로 보인다.**

`MascotSpriteSet.ink` 가 칸마다 알맹이가 상자 어디를 덮는지 재 두고,
`UsageHUDView.petPerchOrigin` 이 그만큼 창을 밀어 놓는다. **상수로 못 박지 마라** —
사용자가 넣은 그림은 칸 안 자리가 또 달라서 우리 부엉이에 맞춘 숫자는 거기서 반드시
틀린다.

맞게 됐는지는 `--probe-perch` 로 본다. **실제로 한 번 그려서 알파를 재고** 예측과
견주므로 좌우 반전·위아래 뒤집기 실수가 여기서 잡힌다.

### 가려진 테두리에는 안 붙는다

**놓는 사람은 보이는 것에 겨냥한다.** 그 자리에 다른 창에 덮인 테두리가 숨어 있으면,
겨냥하지 않은 창에 붙어서 **아무것도 없는 자리에 매달린 것으로 보인다.**

`.optionOnScreenOnly` 목록이 앞에서 뒤 순서라 **자기보다 앞에 있는 창만** 보면 된다.
붙을 자리(그림 상자 + 테두리 안쪽 6pt)가 그것들과 겹치면 그 후보를 버린다.

한동안 이 판정을 뺐다 — "사용자가 직접 끌어다 놓는 것이라 우리가 자리를 고를 이유가
없다"고 봤는데 **거꾸로였다.** 직접 놓기 때문에 오히려 보이는 것만 후보여야 한다.

**진단 표도 같은 통로로 판정한다**(`obstacle` 이 `snap` 을 부른다). 따로 셈하면
표에는 "가능"이 뜨는데 실제로는 안 붙는 자리가 생긴다 — 실제로 그렇게 어긋났다.

### 붙어 있으면 창 층으로 내려간다

펫은 늘 위에 떠 있는 창(`.floating`)이라, 붙은 창이 다른 창에 가려져도 **혼자 앞에 남아
허공에 뜬 것으로 보인다.** 붙어 있는 동안만 `.normal` 로 내려서 남의 창과 같이 가려지게
하고, 붙은 창이 맨 앞으로 오면(`WindowSurvey.locate` 의 `isFront`) 펫도 같이 올린다.
**떼면 반드시 되돌린다** — 안 되돌리면 그 뒤로 펫이 계속 창 뒤에 숨는다.

`NSWorkspace` 앱 활성화 알림으로는 안 된다. 같은 앱 창이 여럿이면(브라우저 창 둘)
붙은 창이 뒤에 있는데도 올려서 다시 허공에 뜬다. **창 목록 순서로 봐야 한다.**

### 붙여 놓은 것은 눌림으로 떨어지지 않는다

**"움직여도 되는지"(`isActive`)와 "붙어 있어도 되는지"(`canStayPerched`)를 갈라 둔다.**
전자에는 눌림(`isPressed`)이 들어 있는데, 그건 메뉴가 떠 있거나 클릭 중이라 **잠깐
멈추는 이유**일 뿐이다. 하나로 묶어 놨더니 붙여 놓은 것을 한 번 누르거나 우클릭 메뉴를
열면 `motion` 이 `.resting` 으로 덮여서, **자세만 매달린 채 배회가 시작됐다.**

떼는 것은 이것뿐이다 — 펫 모드에서 나감 · 창 숨김 · 화면 잠김 · 집어 듦 · 조회 끊김 ·
주간 소진 · 설정 끔 · 붙은 창이 사라짐.

```bash
dong-csu --probe-perch selftest
```

**눈으로는 볼 수 없는 검사다.** 붙었는지는 그림을 보면 알지만 *누르면 떨어지는가* 는
떨어진 뒤 몇 초를 지켜봐야 알 수 있고, 그때는 이미 걸어나가 있다. 여기서 상태 전이를
직접 돌려 본다.

**대조군을 반드시 같이 돌린다.** "붙어 있으면 커서를 안 피한다"는 붙어서 안 피한 것과
글 쓰는 중(`isTypingQuiet`)이라 안 피한 것이 결과가 같다. 검사가 키 입력이 멎기를
5초 기다린 뒤, 붙지 않은 것 하나를 나란히 돌려 그쪽이 실제로 비키는지 먼저 확인한다 —
대조가 성립하지 않으면 **통과로 세지 않고 "판정 못 함"으로 적는다.**

## 지우는 것은 반드시 묻는다

**되돌릴 수 없는 것을 지우는 버튼은 예외 없이 확인을 한 번 받는다.** 설정 창은 목록을
눌러 들어가는 자리가 많아서 손이 스쳐도 눌린다.

- `confirmationDialog` 를 쓰고 지우는 버튼에 `role: .destructive` 를 준다
- **무엇이 몇 개 지워지는지 적는다** — `기록 12개가 지워집니다` 처럼
- 지운 대상을 띄워 놓은 팝업이 있으면 같이 닫는다

지금 걸려 있는 자리는 모든 설정 초기화 · 측정 기록 전체 지우기 · 측정 기록 하나 지우기
셋이다. 지우는 버튼을 새로 만들면 여기에 한 줄 더한다.

## 메뉴

우클릭 메뉴와 메뉴바 메뉴는 `HUDController.populateMenu` 하나를 같이 쓴다.
**여기에 설정 항목을 늘리지 않는다** — 모드·크기·테마·아이콘은 전부 설정 창에 있고,
메뉴에 한 벌 더 두면 두 곳을 함께 고쳐야 하는 데다 자주 누르는 항목이 파묻힌다.
메뉴에는 바로 누르는 것(새로고침·설정·종료)만 남긴다.

## 성능을 숫자로 말할 때

**폴링이 도는 동안 잰 CPU는 못 믿는다.** 사용량 조회 한 번이 애니메이션 몇 분 치보다
비싸서, 창 안에 조회가 들어갔는지에 따라 부호까지 뒤집힌다. 비교할 때는 조회 주기를
길게 막고, **같은 앱에서 조건만 바꿔** 여러 창을 번갈아 잰다.

`ImageRenderer`는 `ScrollView` 안을 그리지 못한다. 스크롤이 필요한 화면은
`isPreviewRender`로 스크롤을 벗긴 형태를 따로 그린다.

### 설정 창 안에서 따로 넘겨보는 목록

변경 내역·측정 기록처럼 **길이가 정해지지 않은 목록은 창을 늘리지 않고 제자리에서
넘겨본다.** 그러려면 위쪽 어딘가의 높이가 못 박혀 있어야 한다 — 바깥 스크롤은 세로
높이를 무한히 제안해서, 그 아래에서 `maxHeight: .infinity` 는 "남는 만큼"이 아니라
"내용만큼"으로 풀린다. `tabBodyHeight` 가 창 높이에서 `chromeHeight` 를 빼서 그
기준을 만든다.

**목록이 시작하는 자리를 재서 맞추는 길은 안 된다.** `GeometryReader` + `preference`
로 해 봤는데, 값이 레이아웃이 끝난 뒤에야 돌아와서 그 판에는 반영되지 않는다
(`.background` 안에서 올린 preference 는 아예 부모로 올라오지도 않는다).

**렌더 통로로는 이게 걸렸는지 알 수 없다** — 그쪽은 스크롤을 벗긴 모습을 그린다.
진짜 창에 얹어 놓고 재는 통로를 따로 둔다.

```bash
dong-csu --probe-layout
```

기록을 4개 넣었을 때와 50개(최대치) 넣었을 때 높이가 같은지 검사하고, 다르면 1로
끝난다. **재는 중인 측정 탭이 창보다 긴 것은 정상이다** — 살아 있는 값이 자리를
많이 쓰는 것이지 목록 탓이 아니라서, 넘치는 만큼은 바깥 스크롤이 받는다.

## 번들 ID

번들 ID는 `com.ldg.dong-csu` (테스트판은 `-test`).

**번들 ID를 바꾸면 UserDefaults 도메인이 통째로 갈린다** — 창 위치·아이콘·크기·펫 설정이
전부 초기화된다. 함부로 바꾸지 않되, 꼭 바꿔야 하면 `HUDSettings.migrateLegacyDefaults`
처럼 **옛 도메인에서 한 번 옮겨 오는 코드를 같이 넣는다.** 샌드박스가 아니라서 읽을 수 있다.

## 서명

손쉬운 사용 권한은 **코드 서명 신원**에 걸린다. ad-hoc 서명은 신원이 없어서 macOS가
바이너리 해시로 앱을 알아보는데, 그 해시는 코드가 바뀔 때마다 달라진다 — 다시 빌드할
때마다 허용해 둔 권한이 풀린다. `./make-signing-cert.sh` 를 한 번 돌려 자체 서명
인증서를 만들어 두면 신원이 고정된다.

**지금은 이 인증서가 없어도 된다.** 앱이 손쉬운 사용 같은 권한을 하나도 안 쓰고,
keychain 은 신원이 고정된 `/usr/bin/security` 를 거친다. 나중에 진짜 권한을 쓰는
기능이 생길 때를 위해 통로만 열어 둔 것이다.

```bash
codesign -dv --verbose=4 build/DongCSU-Test.app 2>&1 | grep Authority
```

권한이 걸리는 기능을 만들게 되면, 확인할 때 **터미널에서 바이너리를 직접 부르면
안 된다.** TCC가 Terminal.app에 권한을 물어서 결과가 거짓이 된다. `open -n
build/DongCSU-Test.app --args …` 로 번들을 통해 확인한다.
