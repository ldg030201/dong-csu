# 캐릭터 만들기

[← 캐릭터](README.md)

**그림 한 장이면 캐릭터가 바뀐다.** 24칸에 자세를 나눠 담은 시트를 넣으면 HUD와 펫이
그걸 읽는다. 기분·걸음걸이·창에 붙기를 판단하는 코드는 한 벌뿐이라 손대지 않는다.

그림은 손으로 그려도 되고 AI에게 시켜도 된다. 여기 적힌 건 **AI에게 시키는 쪽**인데,
캐릭터를 여러 개 뽑아 보면서 실제로 걸리는 것들을 다 넣어 둔 프롬프트가 있어서다.

## 넘기는 것 셋

**여기 다 올려 뒀다.** 캐릭터마다 바뀌는 것은 가운데 하나뿐이다.

| | 무엇 | 캐릭터가 바뀌면 |
| --- | --- | --- |
| ① **캐릭터 프롬프트** | 종·색·몸 비율. 공통이 비워 둔 자리를 채운다.<br>예시 → [부엉이](owl.md#그림-시트-프롬프트) · [라쿤](raccoon.md#그림-시트-프롬프트) | **이것만 바뀐다** |
| ② [`prompt.txt`](prompt.txt) | 규격·화풍을 정하는 **공통 프롬프트**. 종도 색도 가정하지 않는다 | 그대로 |
| ③ [`frame.png`](frame.png) | **빈 틀** — 칸 선만 그은 1543x1029. 캔버스와 칸 자리만 알려 준다 | 그대로 |

순서대로 넘긴다 — ①을 치고, 바로 밑에 ②를 통째로 붙이고, ③을 첨부한다.

### 자세를 시시콜콜 적지 않는다

**공통 프롬프트에 있는 것은 앱이 실제로 재는 값뿐이다.** 칸 크기, 배경 알파,
다리가 전체 키의 15%, 창 테두리에 닿는 지점과 깊이 — 이런 것들은 코드가 그대로
읽으므로 어긋나면 그림이 안 붙는다.

**어느 관절을 얼마나 굽힐지는 안 적는다.** 한동안 매달린 자세를 다섯 항목으로
쪼개 적어 놨는데(팔뿌리 위치·어깨 높이·손 모양·팔 각도·뻗은 길이) 오히려
어색해졌다. 그리는 쪽이 자연스럽게 낼 것까지 막아서다. **"팔로 잡고 매달린다"
까지만 적고 나머지는 맡긴다.**

> [!CAUTION]
> **같은 캐릭터를 고쳐 달라고 그 시트를 붙이지 마라.** 자세까지 통째로 베껴 온다.
> 지금 쓰는 시트를 붙이고 "이 여섯 가지를 고쳐 달라"고 적어 봤는데 **여섯 개가 하나도
> 안 고쳐진 그림이 왔다.** 옆모습 두께도, 다리도, 목덜미 잡힌 자세도 전부 옛 그림
> 그대로였다. 같은 캐릭터를 다시 받을 때는 **빈 틀**을 붙인다.
>
> **다른 캐릭터의 완성 시트는 화풍 견본으로 붙여도 된다.** 다만 `prompt.txt` 맨 위
> "첨부한 그림을 어떻게 볼 것인가"가 **자세는 보지 말라고** 못 박고 있어야 한다.
> 그게 없던 동안 부엉이 시트를 붙이고 라쿤을 받았더니, 글에 "손으로 잡는다"라고 적혀
> 있는데도 **부엉이처럼 발로 거꾸로 매달린** 그림이 왔다.


## 1. 그림 받기

**세 가지를 한 번에 넘긴다.** 그림 만드는 AI라면 어디든 되지만, 여기 적힌 값들은
GPT로 재면서 맞췄다.

1. 무슨 캐릭터인지 **직접 친다** — 종·색·몸 비율까지 적는 편이 낫다. 안 적으면 매번 다르게 온다

   공통 프롬프트는 **캐릭터를 하나도 가정하지 않는다.** 종도 색도 hex도 없고, 부위도
   `붙잡는 앞다리`·`주둥이`처럼 역할로만 부른다. 그러니 **그 캐릭터가 무엇인지는 전부
   이 글에서 와야 한다.** 특히 **"이 캐릭터의 붙잡는 앞다리는 무엇인가"**를 반드시
   적는다 — 부엉이면 날개고 라쿤이면 팔이다. 안 적으면 벽붙기 칸이 엉뚱한 데로 간다.

   ```
   <어떤> <무슨 동물> 캐릭터의 스프라이트 시트를 만들어 줘.
   첨부한 견본은 칸 배치만 보고, 캐릭터는 새로 그린다.

   몸매   실루엣 한 줄. 옆모습이 홀쭉해지지 않게 여기서 못 박는다
   머리   크기·머리 위에 붙은 것
   얼굴   눈 크기와 자리
   주둥이 부리·코·입 중 무엇인지
   앞다리 ** 이 캐릭터의 "붙잡는 앞다리" 는 <무엇> 이다. ** 생김새
   뒷다리 ** 길이는 전체 키의 15%, 몸통 아래로 보인다 **
   색     쓸 색을 hex 로 못 박는다. 몇 색만 쓸지도 적는다
   ```

   **다 채운 예시는 [부엉이 문서](owl.md#그림-시트-프롬프트)에 있다.** 그대로 베껴서
   종·색·부위만 갈아 끼우면 된다.

2. 바로 밑에 [`prompt.txt`](prompt.txt)를 **한 글자도 고치지 말고 통째로** 붙인다
3. **그림 한 장을 첨부한다.** 둘 중 하나다.

   | | 언제 | 얻는 것 |
   | --- | --- | --- |
   | [`frame.png`](frame.png) **빈 틀** | 기본. 같은 캐릭터를 다시 받을 때는 **반드시 이쪽** | 캔버스·칸 자리 |
   | **다른 캐릭터의 완성 시트** | 화풍을 맞추고 싶을 때 | 캔버스·칸 자리 + 선 굵기·색감 |

   크기가 어중간하게 오는 것은 알려진 실패 모드라, 캔버스만은 그림으로 못 박아 주는
   편이 낫다. 빈 틀을 다시 뽑으려면:

   ```bash
   dong-csu --dump-sprites frame.png sheet rules empty
   ```

   어느 쪽을 붙이든 **자세는 글이 정한다** — `prompt.txt` 맨 위가 그걸 못 박는다.

> [!TIP]
> **한 칸만 고쳐 달라고 다시 부탁하지 않는다.** 고친 칸만 화풍이 튀어서 나머지와
> 안 맞는다. 자세 하나가 마음에 안 들어도 **통째로 다시 받는 편이 싸다.**
>
> **"이 캐릭터를 그대로 지켜라"라고 적지 마라.** 그렇게 써 봤는데 결과가 뻣뻣해졌다.
> 첨부한 시트가 이미 그 일을 하고 있어서, 글로 한 번 더 못 박으면 그림을 베끼는
> 쪽으로만 몰린다. **"캐릭터는 새로 그린다"로 두면** 첨부를 참고하면서도 더 나은 것이
> 나올 자리가 남는다. 같은 캐릭터를 다시 받는 것도 마찬가지다.

## 2. 규격으로 다듬기

받은 그림은 대개 배경이 흰색이고 칸 선이 그어져 있다. 그걸 벗겨서 규격 시트로 만든다.

```bash
dong-csu --prep-sheet ~/Downloads/받은그림.png mascot.png
```

| 하는 일 | |
| --- | --- |
| 배경 지우기 | **이미 투명하면 안 한다.** 단색이면 통째로, 흰색·회색이면 테두리에서 번져 들어가며 |
| 안개 걷기 | 그림에서 떨어져 나온 반투명 그림자. 가장자리 계단은 남긴다 |
| 칸 선 지우기 | 배경과 같은 색으로 친다 |
| 부스러기 지우기 | 몇 픽셀짜리 점은 그림이 아니다 |
| 자리 맞추기 | 칸마다 가운데로. 걷기·뛰기는 **머리** 기준 |

### 이미 투명하게 온 그림은 색으로 안 지운다

**칸 자리는 규격으로 정해져 있다.** 1536x1024 를 6x4 로 균등하게 가르고 경계
안쪽만 훑으므로, 배경이 무엇이든 칸 선이 그어져 있든 **찾을 필요가 없다.**
색으로 지우는 길은 배경이 진짜 픽셀로 그려져 왔을 때만 쓴다.

알파를 들고 온 그림에까지 그걸 태웠더니 **라쿤의 윤곽선과 발이 통째로 날아갔다.**
지울 배경이 없으니 가장자리에서 배경색을 추측했는데, 거기 있던 것은 배경이 아니라
그림 둘레에 번진 **짙은 남색 그림자**였다. "밝기 0~37 이 배경" 으로 잡혔고 윤곽선
(`#2B2521`)과 발이 같은 범위였다. 66% 를 지웠다.

지금은 가장자리 띠가 **70% 넘게 비어 있으면** 이미 투명한 그림으로 보고 색을 안
건드린다. 같은 그림에서 지우는 양이 66% → 6% 가 됐고, 6% 는 안개뿐이다.

**안개는 걷어낸다.** 그 반투명 그림자는 눈에 뿌연 테로 보이고, 칸 잉크 상자를
부풀려 캐릭터를 작게 만든다. 다만 **가장자리 계단은 남긴다** — 반투명이라고 다
지우면 윤곽선이 톱니가 된다. 그림의 일부인 반투명은 불투명한 픽셀에 붙어 있고
그림자는 떨어져 있어서, 2px 안에 불투명한 것이 있는지로 가른다.

**걷기·뛰기 여섯 칸은 바닥에 붙이지 않는다.** 그 칸끼리 가장 낮은 것을 땅으로 삼고
나머지는 그려진 만큼 띄운다 — 뛸 때 두 발이 뜨는 것이 그림에 들어 있어서, 바닥에
붙이면 그게 사라진다.

## 3. 넣기

기본 캐릭터를 **갈아 끼우는** 것이면 파일 하나면 된다.

```bash
cp mascot.png mac/Resources/mascot.png
```

`build.sh`가 이걸 그대로 번들에 넣는다. 다시 빌드하면 바뀐다.

### 캐릭터를 하나 **더** 넣을 때

셋을 맞춘다. **이름 셋이 전부 같아야 한다** — 어긋나면 그 캐릭터만 조용히 격자
부엉이로 떨어지고, 화면에는 아무 말도 안 나온다.

| | |
| --- | --- |
| `mac/Resources/<이름>.png` | 다듬은 규격 시트 |
| [`ClaudeIconStyle`](../../mac/Sources/DongCSU/ClaudeIcon.swift) | 케이스 하나 + `sheetResource` 에 `"<이름>"` + 제목 둘 |
| [`build.sh`](../../mac/build.sh) 의 `for extra in …` | `<이름>` 한 낱말 |

`sheetResource` 가 값을 주면 나머지는 따라온다 — 아이콘 목록·창에 붙기·폭 재기가
전부 `usesSheet` 하나만 본다. **캐릭터 이름으로 견주는 코드를 새로 쓰지 마라.**

넣었으면 잰다. **캐릭터 이름을 안 붙이면 부엉이를 재는 것**이라 아무것도 확인이 안 된다.

```bash
dong-csu --probe-mascot <스타일이름>   # 칸이 몇 개 읽혔나
dong-csu --probe-perch  <스타일이름>   # 붙는 자리가 그림과 맞나
```

마지막으로 [`docs/characters/`](.) 에 문서를 만들고 [목록](README.md)에 한 줄 더한다.
그리드·팔레트·프롬프트는 소스가 아니라 거기에 쓴다.

> [!WARNING]
> **아직 사용자 폴더로는 못 바꾼다.** 이 문서는 한동안
> `~/Library/Application Support/<번들 ID>/mascot/`를 안내했는데 **그 경로를 읽는
> 코드가 없다.** `MascotSpriteSet`을 만드는 곳이
> [`MascotSpriteStore.bundled`](../../mac/Sources/DongCSU/MascotSprite.swift) 하나뿐이고
> 그건 번들만 본다. `mascot.json`(`MascotAtlas`)도 적히기만 하고 읽는 곳이 없다.
> 지금 캐릭터를 바꾸는 길은 번들 그림을 갈아 끼우고 다시 빌드하는 것뿐이다.

## 규격

**`1536 x 1024`** 로 받아서 **`1543 x 1029`** 로 다듬는다. 한 칸은 256 x 256이고,
다듬은 쪽에는 칸 사이와 바깥에 1px 선이 들어간다.

```
가로 = 6칸 x 256 + 7선 x 1 = 1543
세로 = 4칸 x 256 + 5선 x 1 = 1029
칸 (열 c, 행 r) = x: 1 + c*257, y: 1 + r*257, 256 x 256
```

**선은 어느 칸에도 안 들어간다.** 칸 자리를 선 굵기만큼 밀어 놨기 때문에, 선을 지우든
남기든 그림에는 영향이 없다.

| | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| **1줄** 서 있을 때 | 평소 | 평소+눈감음 | 졸림 | 졸림+눈감음 | 탈진 | — |
| **2줄** 움직일 때 | 걷기A | 걷기B | 졸린걷기A | 졸린걷기B | 뛰기A | 뛰기B |
| **3줄** 잡히고 매달릴 때 | 들림 | 들림+눈감음 | 아래매달리기 | 〃+눈감음 | 벽붙기 | 벽붙기+눈감음 |
| **4줄** 그 밖 | 걸터앉기 | 걸터앉기+눈감음 | 어지러움 | 죽음 | — | — |

**옆모습은 여덟 칸이다** — 2줄 여섯 칸과 벽붙기 둘. 나머지는 정면이고, 오른쪽으로
걷는 그림·오른쪽 벽에 붙은 그림은 좌우 반전으로 만든다.

### 창에 붙는 세 칸

걸터앉기·아래매달리기·벽붙기는 화면에 떠 있는 **다른 앱 창의 테두리**에 걸어 두는 데 쓴다.
셋의 규칙이 하나다 — **붙잡는 부위가 창 안으로 넘어간다.**

| 창의 어느 테두리 | 칸 | 창 안으로 넘어가는 것 | 깊이 |
| --- | --- | --- | --- |
| 위 | 걸터앉기 | 뒷다리와 발 | 캐릭터 세로의 **0.15** |
| 아래 | 아래매달리기 | 잡는 부위 — **손이 있으면 손**, 없으면 발 | 캐릭터 세로의 **0.15** |
| 좌우 | 벽붙기 | 붙잡는 앞다리 | 캐릭터 가로의 **1/4** |

**넘어간 부위도 그대로 다 보인다.** 붙어 있는 동안 마스코트가 그 창보다 위 층에
그려져서, 창에 가려지는 게 아니라 창 면 위에 얹힌다.

전에는 그림 전체를 테두리 **바깥**에 딱 맞춰 놓았다. 그러면 잡는 부위가 창에 닿기만
하고 넘어가질 않아서, 옆에 붙었을 때 껴안은 게 아니라 벽에 부딪친 것으로 보였다.

## 걷기가 걷는 것처럼 안 보일 때

여기서 제일 오래 막혔다. **걷기 두 칸은 "왼발 / 오른발"이 아니다.**

| | |
| --- | --- |
| 걷기A | 두 다리를 앞뒤로 **벌린** 순간 |
| 걷기B | 두 다리가 몸 아래에서 **만나 겹친** 순간 |

이 둘을 번갈아 보여주면 보는 사람이 네 박자로 읽는다 — 벌림(왼발이 앞) → 모음(두 발이
스쳐 지나감) → 벌림(오른발이 앞) → 모음. **모음 칸이 없으면 이 착각이 안 걸린다.**

벌린 그림 두 장에서 발만 서로 바꿔 그리면 걷는 게 아니라 **발 색이 바뀌는 것**으로
보인다. 실제로 그렇게 받았고 그렇게 보였다 — 그때 두 칸의 발 위치 차이가 2~3px,
몸 폭의 1.5%였다. 화면에서 40pt로 줄면 0.5픽셀이라 아예 안 보인다.

지금 시트는 벌린 쪽 두 발 간격이 몸 폭의 46%, 모은 쪽은 두 발이 한 덩어리다.

**뒷다리만 어둡게 칠하지 않는다.** 밝기 차가 크면 뇌가 그걸 다리가 아니라 그림자로
읽어서, 발이 바뀌는 게 아니라 색이 바뀌는 걸로 보인다. 앞뒤 구분은 윤곽선으로 한다.

## 안 될 때

| | |
| --- | --- |
| 배경이 안 지워진다 | 편집기의 회색 바둑판을 **진짜 픽셀로** 그려 온 것이다. 다시 받는다 |
| 윤곽선·발이 사라졌다 | 아래 참고. 고쳤지만 같은 꼴이 또 나오면 여기를 본다 |
| 칸이 하나로 잡힌다 | 위와 같은 원인. `--prep-sheet` 가 그렇다고 알려 준다 |
| 옆 칸 그림이 같이 보인다 | 자세가 칸 밖으로 넘쳤다. `--prep-sheet` 가 안쪽으로 되민다 |
| 상태마다 크기가 요동친다 | 칸마다 캐릭터 키가 다르다. 5px 넘게 차이 나면 눈에 띈다 |

규격에서 벗어난 그림은 좌표를 손으로 적어서 구제할 수 있다. 자세한 건
[macOS 작업 규칙](../../mac/CLAUDE.md#그림-마스코트).
